Booot 7.4 C++ Port — Stage 20 change log

Search-fidelity corrections:
- SearchEngine::evaluate now returns raw evaluation scores. TT static-evaluation
  entries retain raw NNUE scores; consuming nodes apply ScaleEval for the
  current rule-50 clock and correction histories.
- Improving detection and correction-history updates use the scaled static
  evaluation before any TT-bound replacement, matching Pascal Tree[].StatEval.
- LMR retains negative reductions and converts them to the original one-ply
  deeper child search.
- LMR now uses the Pascal GetHistoryValue weighting rather than the move-order
  quiet-score weighting.
- Restored the TT-PV/low-PV, hash-capture, cut-node, killer/counter, check,
  quiet-singular, and history LMR adjustments.
- Restored Pascal's post-LMR zero-window re-search depth adjustments.
- Root LMR now applies its PV adjustment only for a PV window and retains the
  +80 re-search extension through the final full-window search.

Verification:
- GCC and Clang complete Stage 1–15 host test suites: PASS.
- GCC and Clang Stage 19 focused tests; AArch64 SDOT code-generation probe: PASS.
- GCC ASan/UBSan Stage 1–8 plus additional search and UCI sanitizer tests: PASS.
- Android NDK production build and Galaxy A16 playing-strength test: NOT RUN.
  The Stage 19 source archive lacks the three original production networks.


Stage 20.1 Android compile-error hardening:
- Search records the moving piece and parent-position key directly from the
  parent Position before make_child(), no longer reading Undo::moving_piece or
  Undo::key at search call sites.
- booot_search.hpp directly includes booot_board.hpp for the Position/Undo API.
- The Stage 20 modified-files overlay now includes the Stage 19 compact-undo
  board and NNUE compatibility set to prevent mixed-stage headers/sources.
- GCC full Stage 1-15/perft, Clang quick Stage 1-15, and GCC search/UCI
  ASan/UBSan checks pass. Android NDK build remains unverified locally.


Stage 20.2 Android linker hardening:
- Android C++ and assembly translation units are compiled separately into a
  temporary object directory and that exact object list is passed to LLD.
- NDK llvm-nm verifies that booot_nnue.o defines both public NNUE symbols
  required by booot_uci.o and booot_nnue_move.o before the final link.
- The temporary object directory is removed on success or failure.
- A missing/stale NNUE implementation now produces a targeted pre-link error
  identifying the required functions and companion files.
